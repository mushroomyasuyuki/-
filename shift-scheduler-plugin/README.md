# シフト作成（マルチテナント）プラグイン

設計：リポジトリ直下の `shift-plugin-design.md` と `shift-plugin-detail-design.md`。

## 現在の範囲（v0.3.1）

**フェーズ1：テナント基盤**
- 無料登録 → メール認証 → 専用ページ、ログイン、スタッフ招待（お客様側のログインは専用ページのみ。`wp-login.php` からは不可）
- ロール：お客様の管理者／副管理者／スタッフ。お客様側のユーザーはWordPress管理画面に入れない
- スタッフ管理と、スタッフ数の上限チェック。管理者自身のメールアドレスで「招待」すると、自分のアカウントをスタッフに紐づけ
- 無料期間（2か月・カード不要）と、期限切れ後の「閲覧のみ」

**フェーズ2：シフトの材料（v0.3.1）**
- 勤務区分（名前・略称・時間・休憩・夜勤・色）。業種のひな形つき。日をまたぐ夜勤にも対応
- ルール設定：全体のルール（連勤上限・勤務間の休息・公休日数・夜勤回数・夜勤明けの休み）と、必要人数（曜日ごと＋特定の日の上書き、30分単位、役割・資格の指定）
- 希望の収集（管理者）：期間と締切を決めて受付、提出状況の確認、受付の終了・再開
- 休みのまとめて設定（管理者）：日付の範囲（＋曜日の指定）× 全員または選んだスタッフに「希望休」「出勤不可」を設定・解除。定休日や年末年始などに使う。管理者が設定した日は、スタッフは変更できない
- 希望休の提出（スタッフ。管理者がスタッフに紐づいている場合は管理者も）：期間内の日ごとに「希望休」「出勤不可」を選んで提出。締切まで修正可

**フェーズ3：シフト表と自動作成（v0.3.1）**
- シフト表（期間を決めて作成）：スタッフ×日付の表で、セルを押して勤務区分・時間指定・休み・固定を設定。1人1日1勤務
- 自動作成：ルール・必要人数・希望休・出勤不可を踏まえて案を3つ作り、選んだ案を反映。計算はブラウザ内（別スレッド）で実行するので、さくらのレンタルサーバーに負荷がかからない。固定した勤務は動かさない
- 表示：必須ルール違反（赤枠）、希望休との重なり（黄枠）、人数が足りない時間帯の一覧、スタッフごとの出勤日数・時間
- 保存・公開／取り下げ、元に戻す（直前の自動作成・一括消去）
- スタッフ向け「シフトを見る」：公開されたシフトを閲覧。設定で「全員分」か「自分の分だけ」を選べる（自分の分だけの場合は、APIも他人の分を返さない）

**自動作成のルールの意味**
- 必須（守れない案は違反として表示）：勤務できる曜日、出勤不可・管理者が設定した休み、夜勤に入れるか、連勤の上限、勤務間の休息、月の夜勤回数、月の公休日数（期間が月の一部のときは日数で按分）、夜勤明け（夜勤の翌日と翌々日は勤務なし。「夜勤の後は明けと翌日を休みにする」を有効にしたとき）
- できるだけ守る：スタッフの希望休、必要人数（30分単位。不足は1人30分ごとに減点、多すぎる分も少し減点）
- 同じ時間帯に「特定の日」の必要人数があれば、曜日の設定より優先

**運営者向けの統計（WordPress管理画面の「シフト作成」メニュー）**
- 「利用状況・お客様一覧」：ご利用中のお客様の数（社）、有料契約中・無料期間中・閲覧のみ・停止中の内訳、14日以内に無料期間が終わる社数、今日・7日・30日の新規登録、30日以内・7日以内に利用した社数、スタッフの合計、作成されたシフト表の数、月別の新規登録（直近12か月）、業種別
- お客様の一覧：事業者名・業種・状態・管理者のメール・無料期間の終了日・スタッフ数・シフト表の数・最終利用日。事業者名で検索、状態で絞り込み、CSVでダウンロード（表計算ソフトで式として実行されないよう処理）
- お客様のシフトの中身（勤務・希望休）は、集計にも一覧にも出さない。WordPressの管理者だけが見られる
- 「ページのURL」：登録・ログインページのURLの案内（旧「設定 → シフト作成」から移動）

**まだ入っていないもの**
- サーバー側でのルール違反の再チェック（今は、時刻・スタッフ・勤務区分・期間の整合性のみ確認。ルール違反は画面側で判定）
- 労働時間の公平化、週・月の労働時間の上限、1日に複数の勤務（中抜け）
- PAY.JP決済・プラン設定画面・運営用の管理画面



## お客様ごとのデータ分離

- 全テーブルに `tenant_id`。データ操作は `SS_Repo`（常にお客様IDで絞り込み）だけを通す。
- お客様IDはログイン中ユーザーの所属から決める。URL・フォーム・JSONの値は使わない。
- 他のお客様の `/s/<ID>/` を開くと、存在の有無が分からない「見つかりません」を返す。
- テスト（WordPress本体なしで実行可能）：
  - `php tests/test-tenant-isolation.php` … SQLに必ずお客様IDの条件が付くこと
  - `php tests/test-flow-sqlite.php` … お客様A・Bの2社で、他社のスタッフ・勤務区分・ルール・期間・希望に触れないこと、希望の提出、閲覧のみの制限
  - `php tests/test-validation.php` … 勤務区分・必要人数・期間の入力検証
  - `php tests/test-login-block.php` … wp-login.php経由のお客様ログインの拒否
  - `php tests/test-stats-sqlite.php` … 運営者向けの統計・お客様一覧・CSV・管理画面の表示
  - `sh tests/check-no-direct-db.sh` … 画面・APIが `$wpdb` を直接使っていないこと
  - `node tests/test-solver.js` … 自動作成・ルール違反チェック（飲食12名・介護16名など。違反0・不足0になること）
  - `NODE_PATH=<playwrightの場所> node tests/browser/test-schedule-ui.js` … シフト表の編集画面を、Chromiumで実際に操作して確認

## 設置

1. ZIP（リポジトリ直下の `shift-scheduler-0.3.1.zip`）を、WordPress管理画面の「プラグイン → 新規追加 → プラグインのアップロード」から入れて有効化（テーブル・ロール・初期プランが作られる）。
2. 設定 → シフト作成 に、登録ページ・ログインページのURLが表示される。メニューやボタンにそのURLを設定する（WordPressの固定ページとしては作られない）。パーマリンクが「基本」でも `/?ss_page=register` の形式で表示できる。
3. （任意）利用規約のURL：オプション `ss_terms_url` に設定。
4. メール送信が不安定な場合は、SMTPプラグインを併用する。

## 注意

- **プラグインを「削除」すると、お客様のデータはすべて消えます（元に戻せません）**。テーブル、お客様側のユーザー、ロール、設定が対象です。「無効化」では消えません。本番で削除する前に、必ずバックアップを取ってください。
- パスワード再設定は、WordPress標準の画面（`wp-login.php?action=lostpassword`）を使う。
